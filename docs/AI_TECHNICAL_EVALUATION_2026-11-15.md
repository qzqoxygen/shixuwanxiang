## 实际实现

### 基于本地知识库的检索增强生成

统一运行数据仍为 `data/cultural-cases/cases.json`，与最终main数据完全一致；原77条及2pending、稳定ID与来源不改，新20条来自main既有补采，不是本轮AI造数。运行接口仍只公开verified。没有向量数据库、Embedding模型或新增付费检索服务，准确名称是**基于本地知识库的检索增强生成**，不是向量RAG。

`cultural-retrieval.ts`读取现有知识集合，结合中文分词、查询词归一化和小型别名表完成联合检索：

- 使用节气、明确省市/地区、类别、案例名及关键词约束，不允许精确标题绕过相反的地区/节气/类别。
- 支持“沪上→上海”“江浙→江苏浙江”“冬节→冬至”“画九→九九消寒图”“萝卜丸子→萝卜圆子”等表达；别名只帮助查候选，不改变实体名称或文化事实。
- 保留显式追问的上文维度，新地区覆盖旧地区，新增类别继续取交集；助手旧回答不是证据。
- 对标题、别名、地域、简介和关联依据加权排序，多省比较预留各省名额，避免一省占满结果。
- 不相关的陌生习俗、明确矛盾条件或未覆盖地区返回无匹配；pending不能被标题或别名提升为公开记录。
- 修复了“漠河北极村”内嵌“河北”的误判和“那只看饮食类”被拆成伪关键词的问题。删除会混淆黑米与乌米饭制作的查询别名，保留有依据的“乌饭”查询。

每次实际search/compare产生最多8条诊断，含筛选维度、匹配策略、候选/匹配数量、选中ID、命中字段和排序分数。不记录系统提示词，不把检索分数当作事实置信度，不新增敏感日志。

### 六工具协同与重复控制

复用既有search、show、highlight、open、节气信息和跨省比较工具，仍由DeepSeek `tool_choice:auto`选择。保留最多2轮、每轮4调用、单工具5秒/输出100000字节、整链路52秒、取消和明确错误。地图依旧只接受三种白名单操作，失败不应用部分批次，前端revision拦截过期响应。

新的依据模式会复用同一请求内**参数相同且已经成功的只读工具结果**。前端显示“复用…结果”，事件标记 `reused:true`，不会把复用算作新执行。失败查询不缓存，地图操作也不缓存；不同请求不共享用户资料。失败后模型可以在既有调用预算内调整参数再查，最终事件如实保留；有工具失败时仍沿用保守策略，不返回地图批次。

联调发现最终回答中的悬空数字引用会在runner提前报错，绕过已有修复；本轮将最终来源/地图声明检查纳入同一个受限修复预算，独立runner仍默认严格拒绝。不得声称尚待用户确认的高亮/详情已经应用；修复只再生成文字，不重跑已经执行的工具。

### 证据链与程序化一致性检查

`answer-evidence.ts`重新读取服务端canonical集合，检查：

1. ID存在且verified；标题、节气、省份/关联省、地区、类别、正文、关联依据及全部来源元数据与实体一致。
2. `[案例N]`只能指向本轮实际返回的案例；`[N]`只能指向本轮实际联网结果。未知、过期和异常编号拒绝。
3. URL必须来自这些实体或本轮搜索；来源不由模型补造。
4. 对句内明确提到的完整已知案例名称及明显错误节气/省份做有限一致性检查。比较、否定和标题内部地名谨慎处理，避免机械误拒。
5. 错误来源进入已有受限修复，最多再生成一次；仍不合法则返回真实错误，不能发布伪造成功。

这个检查能证明**实体字段、归属和引用关联**一致，不能证明每句历史解释真实。证据包固定标记 `statementTruth:false`，明确提示“仅校验实体、归属与引用关联；模型解释未经逐句事实核验”。没有采用模型自评置信度。

证据类型区分本地已核验案例、本轮实时搜索、模型一般知识/生成解释、证据不足。来源访问说明仍保留，不把外链200当成事实核验，也不把原文不可达直接当作记录不存在。

### 最小界面改动与旧兼容

知时聊天复用原工具标签、地区案例卡、原文、地图和制卡入口，增加一个可展开的“回答依据与检索说明”：展示本轮检索实体、节气/地域、已引用或未引用状态、真实来源、别名识别和无匹配提示；实时联网与归档案例各自标识。没有思维链、系统提示词或原始工具参数。

为兼容旧V1客户端严格schema，新界面发送可选 `includeEvidence:true`。只有显式请求的新V1返回 `evidence` 和 `retrievalDiagnostics`，并启用只读结果复用标记；无此字段的旧V1与无版本旧聊天继续原响应结构。原多轮、地图revision、案例详情、造物及节气走访入口均保留。

```text
用户问题/显式追问 + 已校验地图context
    → DeepSeek自主选择现有六工具
    → 本地归一化/联合检索/排序/真实实体与来源
    → DeepSeek依据工具结果生成
    → canonical字段 + 引用编号/URL + 有限明确矛盾检查
    → 受限修复或真实错误
    → 回答 + 四类依据 + 实际工具记录
    → 用户点击地图批次 → 客户端重验 → 原子应用 → 案例详情/制卡
```

实时问题仍先由服务端请求DeepSeek官方Search，再提供实际摘要给模型；搜索失败可继续稳定背景问答，证据标为失败，不声称已联网。

搜索判定移除明确否定的搜索动作和“未经检索的来源”等来源要求，避免普通知识问题仅因出现“检索”二字就触发联网；保留今年/最新/天气等实时信号与相关追问继承。

## 限制

测试集命中率和引用有效率不是所有自然语言问题的正确率。别名表有限；程序不能证明未明示的历史推断或完整语义蕴含。模型选工具仍有随机性，外部搜索和网络可能失败；仍需按实际错误反馈。手机视口模拟不等于实体手机或运营商线路；本轮不部署，所以不能声称公网上线或赛场网络已经验收。模型解释、原创文案与已核验档案仍应区别对待。
